Every secret of an environment lives in the repository, encrypted with
[SOPS](https://github.com/getsops/sops) to the [age](https://github.com/FiloSottile/age) public
keys of the people who run it. This page describes the files, who can decrypt them, and how to set
up an environment's secrets. The pinned versions are SOPS 3.13.3 and age 1.3.2.

## 1. Layout

```
infra/secrets/
  .sops.yaml                 creation rules, generated by sync-recipients.sh
  recipients/<env>.txt       age public keys per environment, one per line
  sync-recipients.sh         regenerates .sops.yaml and re-encrypts to the lists
  new-secrets.py             generates one environment's secrets file
  rotate-secrets.py          generates new values for a rotation
  <env>/secrets.enc.yaml     the platform's secrets (Ansible), SOPS-encrypted yaml
  <env>/ca.enc.yaml          the internal CA of the private network (controller only)
  <env>/tls.enc.yaml         the CA bundle and one key and certificate per node (ansible.md section 6)
  <env>/tofu.enc.env         OpenTofu's credentials (opentofu.md, "Secrets handed to OpenTofu")
```

An environment gets a creation rule in `.sops.yaml` only once its recipients list exists. For an
environment without a list, `sops encrypt` refuses with `no matching creation rules found`, so
nothing is ever encrypted to an unreviewed key.

## 2. Who decrypts

Only people. Each recipient is a person's age public key. The nodes never hold an age
identity: the Ansible `secrets` role decrypts on the controller with the operator's
identity (`SOPS_AGE_KEY_FILE`, else `~/.config/sops/age/keys.txt`) through
`community.sops.load_vars`, and writes per-service env files on each node:

- `/etc/veristar/env/` is `root:root 0700`, every file in it `root:root 0600`.
- Each service gets only its own keys (`roles/secrets/templates/<service>.env.j2`), read
  by Docker Compose's `env_file`.
- Config files that must carry a credential (NATS, Patroni) are written by the edge and
  core roles with mode 0600; Patroni's is owned by the container's postgres user.
- Every task that handles a value runs with `no_log`.

The `secrets` role installs SOPS and age on the controller from their GitHub releases,
checked against pinned SHA-256 sums (`infra/ansible/vars/pins.yml`).

## 3. Contents of `<env>/secrets.enc.yaml`

Generated (random, by `new-secrets.py`): PostgreSQL superuser and replication passwords,
Patroni REST password, Umami database password, `APP_SECRET` and admin password,
`UMAMI_USER_PASSWORD_KEY`, the Umami retention role password, `OAUTH_STATE_KEY`, the
five platform role passwords, one NATS password per service user with its bcrypt hash,
and the NATS route password with its hash, and for monitoring the Grafana admin
password, the `postgres_exporter` password, the probe metrics token and the Gatus
external-endpoint token, and the usage report signing key pair (`report_signing_seed`, a
Stellar secret seed, and `report_signing_key`, its public account id; generated with the
`cryptography` package that ansible-core brings into the controller venv). The hashes are
generated once with the passwords, so the NATS server config does not change on every
converge. A file made before the monitoring keys existed is refused by the `secrets` role,
naming the missing key; add each with `sops edit` and a value from `openssl rand -hex 32`. A
file made before the report key existed gets the pair from `platformctl report keygen`, written
with `sops set --value-file` ([secret rotation](../runbooks/secret-rotation.md#the-usage-report-signing-key)).

Values you provide (read from the environment of `new-secrets.py`, never generated, left out
when unset; [prerequisites.md](prerequisites.md) describes each):

| Key | Environment variable | Required |
|---|---|---|
| `github_client_id`, `github_client_secret` | `SA_GITHUB_CLIENT_ID`, `SA_GITHUB_CLIENT_SECRET` | on core nodes |
| `cloudflare_api_token` | `SA_CLOUDFLARE_API_TOKEN` | on nodes that issue certificates by DNS-01 |
| `ghcr_pull_token` | `SA_GHCR_PULL_TOKEN` | when `sa_registry_login` is set |
| `alertmanager_discord_webhook_url`, `gatus_discord_webhook_url` | `SA_ALERTMANAGER_DISCORD_WEBHOOK_URL`, `SA_GATUS_DISCORD_WEBHOOK_URL` | optional |

The `secrets` role refuses to converge a node that lacks a required value and names the missing
key. Without the Discord webhooks the observability role configures no push receiver, and the
console's operator Alerts page lists firing alerts ([../operators/alerts.md](../operators/alerts.md)).

## 4. Procedures

Create an environment's file (after its recipients list exists):

```sh
SA_GITHUB_CLIENT_ID=... SA_GITHUB_CLIENT_SECRET=... SA_CLOUDFLARE_API_TOKEN=... \
  python3 infra/secrets/new-secrets.py staging \
  | sops --config infra/secrets/.sops.yaml encrypt --filename-override infra/secrets/staging/secrets.enc.yaml \
      --input-type yaml --output-type yaml /dev/stdin > infra/secrets/staging/secrets.enc.yaml
```

Add a value later: `sops --config infra/secrets/.sops.yaml edit infra/secrets/staging/secrets.enc.yaml`.

**Adding a recipient.** The person generates an identity with `age-keygen` and sends the
public key. Add it to `infra/secrets/recipients/<env>.txt` with a comment naming the
holder, run `infra/secrets/sync-recipients.sh` (it rewrites `.sops.yaml` and runs
`sops updatekeys` on every file of that environment), review the diff and commit both.

**Removing a recipient.** Delete the line, run `sync-recipients.sh`, commit. Re-encryption
only stops the person reading future versions; they may have kept the old plaintext.
Therefore also rotate every value they could read, including the GitHub OAuth client secret
and the Cloudflare token at their providers. What `site.yml` applies by itself after a value changes in the file: the five
platform role passwords (`platformctl db roles`), the NATS passwords and hashes (env
files and a NATS reload), and every env file. What it does not apply, because
bootstrap only creates and never alters them: the Umami database password, the Umami
admin password (`platformctl umami bootstrap` replaces only the seeded one), the
PostgreSQL superuser, replication and Patroni REST passwords, and
`UMAMI_USER_PASSWORD_KEY` (changing it changes every derived Umami password). Their
rotation steps are in [../runbooks/secret-rotation.md](../runbooks/secret-rotation.md);
removing a recipient is a complete rotation only once those steps are done too.

**Losing every identity** makes the files unreadable. Each recipient keeps their identity
in a password manager, and every environment has at least two recipients.

## 5. Setting up an environment, step by step

Staging is shown; production is the same with `production` in every path. Needs the
controller tools of [prerequisites.md](prerequisites.md) with `sops` and `age-keygen` on
`PATH`, the public keys of the recipients, and the values of [prerequisites.md](prerequisites.md).

1. **Each recipient makes an identity** on their own machine and keeps the file private:

   ```sh
   age-keygen -o ~/.config/sops/age/keys.txt
   ```

   Expected: `Public key: age1...`. Only that public key is sent.

2. **List the recipients** in `infra/secrets/recipients/staging.txt`, one public key per line,
   each under a comment line naming the holder (at least two people).

3. **Generate the SOPS rules:**

   ```sh
   SOPS=sops infra/secrets/sync-recipients.sh
   ```

   Expected: `wrote .../infra/secrets/.sops.yaml with <n> rule(s)`, one rule per environment
   that has a recipients list. The rule is `path_regex: (^|/)staging/[^/]+\.enc\.(yaml|env)$` with the listed
   keys.

4. **Create the platform secrets file** with the values you provide, typed into the
   environment of this one command (the values are never written in plain text to disk):

   ```sh
   mkdir -p infra/secrets/staging
   read -rs SA_GITHUB_CLIENT_SECRET; export SA_GITHUB_CLIENT_SECRET
   SA_GITHUB_CLIENT_ID=<oauth app client id> \
     ~/.local/share/veristar/ansible-venv/bin/python infra/secrets/new-secrets.py staging \
     | sops --config infra/secrets/.sops.yaml encrypt --filename-override infra/secrets/staging/secrets.enc.yaml \
         --input-type yaml --output-type yaml /dev/stdin > infra/secrets/staging/secrets.enc.yaml
   unset SA_GITHUB_CLIENT_SECRET
   ```

   Do the same with `read -rs` for `SA_CLOUDFLARE_API_TOKEN`, `SA_GHCR_PULL_TOKEN`,
   `SA_ALERTMANAGER_DISCORD_WEBHOOK_URL` and `SA_GATUS_DISCORD_WEBHOOK_URL` when you use them. The script names every input it
   left out on standard error, for example
   `new-secrets.py: SA_CLOUDFLARE_API_TOKEN unset, cloudflare_api_token left out`. The venv's Python is used
   because the script needs `bcrypt` and PyYAML.

5. **Check** that the file decrypts and holds every key:

   ```sh
   sops decrypt infra/secrets/staging/secrets.enc.yaml | grep -o '^[a-z_]*:'
   ```

   Expected: `sa_secrets_environment:` first, then every generated key of section 3 and the
   values you supplied. Never redirect the decrypted output to a file.

6. **Create the OpenTofu credentials file** `infra/secrets/staging/tofu.enc.env` with the
   variables of [Secrets handed to OpenTofu](opentofu.md#secrets-handed-to-opentofu):

   ```sh
   sops --config infra/secrets/.sops.yaml edit infra/secrets/staging/tofu.enc.env
   ```

   SOPS opens an editor on an empty dotenv file; write one `NAME=value` line per variable
   (`CLOUDFLARE_API_TOKEN` and `TF_VAR_state_passphrase`; Azure needs no secret here, OpenTofu
   uses the operator's `az login`). Make the
   passphrase with `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`; it must be
   at least 16 characters and different per environment.

7. **Issue the private network's certificates** once the inventory exists
   ([opentofu.md](opentofu.md#procedure)), before the first converge:

   ```sh
   make internal-ca ENV=staging
   ```

   Expected: `N certificate(s) issued, ca new, 0 retired ca(s) still trusted`, one certificate
   per edge, core, backup and restore node plus the operators' one, and two new files,
   `infra/secrets/staging/ca.enc.yaml` and `tls.enc.yaml` ([ansible.md](ansible.md) section 6).
   The `secrets` role refuses to converge a node without them.

8. **Commit** `infra/secrets/.sops.yaml`, the recipients list and the encrypted files.
